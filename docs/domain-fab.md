# 반도체 현장 과제 — 어휘와 유형 지도 (결선 대비, 1쪽)

목적: 인터뷰 질문이 현장 말로 나오게, 과제를 받자마자 문제군을 맞히게. **답을 미리 만들지 않는다.** 과제가 FAB 밖(사무·물류·안전·HR)일 수도 있으니 어휘는 참고, 유형 표는 공통이다.

## 어휘 — 실무자 말 → 뜻 → 어디에 쓰나
| 말 | 뜻 | 쓰는 곳 |
|---|---|---|
| 로트(lot)·웨이퍼 | 처리 단위(로트 = 웨이퍼 묶음, 보통 25장) | 디스패칭의 결정변수 |
| 공정 스텝·레시피·re-entrant | 로트가 거치는 수백 스텝, 같은 설비군을 여러 번 재방문 | 스케줄 제약 |
| 설비군(tool group)·챔버 | 같은 공정을 하는 설비 묶음 | 배정 대상 |
| 병목(bottleneck) | 가동률이 가장 높은 설비군(포토 등) | 목적함수 후보 |
| WIP·사이클타임·TAT | 재공 수, 투입→완료 시간 | 성공 기준 숫자 |
| 처리량·가동률·OEE | 산출/시간, 가동 비율 | 성공 기준 숫자 |
| PM(예방정비)·다운타임 | 계획 정지·고장 | 스케줄 제약 또는 목적 |
| 배치(batch) 공정·셋업 | 여러 로트 동시 처리(확산로 등), 종류 전환 비용 | 묶기·순서 제약 |
| 수율(yield)·불량(defect)·SPC | 양품 비율, 관리도 | 분석형 과제 |
| 디스패칭 규칙 | FIFO·EDD(납기)·CR(critical ratio)·SPT | `$optimize` 사다리 0·1단 |
| AMHS·OHT·스토커 | 자동 반송(천장 반송차), 보관 장치 | 경로·배치 과제 |
| 클린룸 등급·베이(bay) | 구역 단위 | 배치 과제의 공간 제약 |

## 유형 → 문제군 → 뼈대 (`$optimize`)
| 현장 고민 | 교과서 문제군 | 결정변수 | 전형적 제약 |
|---|---|---|---|
| 어느 로트를 어느 설비에, 어떤 순서로 | 잡숍 스케줄링·배정 | 로트→설비, 시작 시각 | 설비 용량, 셋업, 납기, PM 창 |
| 센서·카메라·AP를 어디에 몇 대 | 예산 제약 최대 커버 / 집합 커버 / 시설 입지 | 후보 위치×종류×방향 | 예산, 필수 지점, 시야·거리, 차폐 |
| PM을 언제 | 구간 스케줄링 MILP | 설비×시간창 | 동시 정지 상한, 생산 계획 |
| 반송·동선·셔틀 | VRP·최단 경로 | 경로·배차 | 용량, 시간창 |
| 어떤 로트를 묶어 넣나 | 빈 패킹·배치 구성 | 로트→배치 | 용량, 레시피 호환 |
| 급식·자재 배합·예산 배분(공장 밖 운영 과제) | 배합(diet/blending) LP·MILP | 품목×수량(일자별) | 영양·성분 범위, 예산, 다양성·반복 상한, 재고 |
| 수율이 왜 떨어졌나, 설비가 이상하다 | **분석형**(가설검정·트리 모델·시계열 롤링 통계) | — | `$optimize` 대상 아님. 기준선 통계부터. 아래 뼈대 |
| 규칙·설비·인력을 바꾸면 어떻게 되나(what-if), 디스패칭 규칙 비교 | **시뮬레이션형**(이산 사건·대기행렬) | 시나리오 파라미터 | `$optimize` 사다리 0·1단의 평가 도구로도 쓴다. 아래 뼈대 |
| 현황이 안 보인다, 집계가 사람마다 다르다 | **현황·대시보드형**(지표 정의·데이터 품질) | — | 아래 뼈대 |

## 최적화가 아닌 유형의 뼈대 — `$optimize` 대신 이 절로 계획 "모형"·"방법 선택" 행을 채운다 (방법 수준은 사용자가 고른다)
| | 분석형(원인·이상·SPC) | 시뮬레이션·what-if형 | 현황·대시보드형 |
|---|---|---|---|
| 세 줄 | 판정 대상과 단위(로트·웨이퍼·설비·시간창) / 무엇과 비교하나(기준선) / 오판 비용(놓침과 오경보 중 무엇이 더 비싼가) | 엔티티·자원·사건 / 바꿔 볼 파라미터 / 비교 지표(사이클타임·WIP·가동률) | 지표의 분자·분모·단위·집계 창 / 이 숫자를 보고 누가 무엇을 바꾸나 / 데이터 품질 규칙(결측·중복·시간 정렬) |
| 사다리(아래로 갈수록 비용↑) | 0 고정 임계값·전후 비교 → 1 관리도·롤링 통계·그룹 비교(기본 권장) → 2 해석 가능한 모델(트리·회귀)로 변수 좁히기 | 0 손계산(용량÷수요) → 1 과거 데이터 그대로 재생(기본 권장) → 2 확률 시뮬레이션(시드 고정·반복 N회) | 0 정적 집계표 → 1 필터·드릴다운 → 2 임계값 경보 |
| 품질 지표 | 검출률·오경보율(건수로), 기준선 대비 차이 | 현재 상태 재현 오차 %, 반복 간 분산 | 원본 재집계와 일치(건수·합계) |
| 검증 | 시간 순 분리(과거로 만들고 이후로 확인), 알려진 사건 재현, 임계값 극단. 라벨이 없으면 "검출률 미측정"이라고 적는다 | 손계산 가능한 소규모와 대조, 투입 = 산출 + 재공 증가분, 같은 시드 재실행 동일 | 독립 스크립트로 같은 숫자 재계산, 빈 구간·중복 입력 |
| 2차 왕복에 가져갈 2~3안 | 임계값(민감도와 하루 오경보 건수의 맞바꿈) | 바꿔 볼 시나리오와 판단 지표 | 지표 정의(무엇을 분모로) |
| Q&A 답 틀 | "<단위>를 <기준선>과 비교해 <방법>으로 판정했다. 상관이지 인과 확정은 아니다. 약점은 <표본·라벨·기간>, 파급은 <오경보로 생기는 일>, 다음 검증은 <새 기간 데이터·현장 확인>." | "현재 상태를 N% 오차로 재현한 모형에서 <파라미터>만 바꿨다. 약점은 <단순화한 가정>, 파급은 <가정이 깨지는 조건>, 다음은 <실측 대조>." | "<지표>를 <분자/분모>로 정의했고 실무자가 확인했다. 약점은 <데이터 품질>, 다음은 <원본 대조 자동화>." |

## 인터뷰에서 바로 쓰는 질문 어휘
"지금은 이 결정을 누가 어떤 기준으로 하나요", "병목이 어디라고 보시나요", "하루 몇 로트(건)인가요", "예산·대수·시간 상한은요", "꼭 지켜야 하는 곳(필수)과 절대 안 되는 곳(금지)은요", "지금 방식의 결과를 숫자로 알 수 있나요(현재값)". 반대 당사자(비용·안전·품질 부서)의 임계값을 숫자로 받는다.

## 주의
- 도메인 세부 해법을 미리 만들지 않는다(미리 만든 답처럼 보인다). 이 문서는 어휘·분류·방법 뼈대만(코드·정답 없음).
- 실전에서 본 과제들(경로 구성, 장비 배치·선택, 배합·구성)의 공통 형태는 "예산 제약 최적화 + 기준 직접 수립 + 실무자 webUI + Docker"였고 **도메인은 매번 달랐다**(공장 안팎 모두). 결선도 뼈대는 같을 가능성이 크지만 소재는 열어 둔다.
