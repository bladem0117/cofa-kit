# qa-adversarial — 적대적 QA (상한 3사이클)

OMX `ultraqa`의 시나리오 매트릭스와 증거 계약을 가져왔다. 빌드·린트·테스트 체크리스트로는 안 잡히는 결함을 **공격자 모델**로 찾는다. 상태 CLI·HUD는 뺐다.

## 언제 쓰나
- `$verify`가 PASS한 뒤, 제출 전
- 입력을 받거나 외부와 상호작용하는 기능(CLI·API·파서·파일 처리)

## 언제 쓰지 않나
- 실행할 수 없는 순수 문서 작업
- 예산이 빠듯할 때는 정상 경로 + 악성 입력 1클래스만 돌리고 "축소 실행"으로 기록

## 절차
1. **계획**: 목표, 성공 기준, 안전 경계(금지 명령·보존할 파일), 중단 조건, 실행 가능한 표면(명령·서비스·하네스)을 적는다. 완료 기준: 아래 매트릭스가 채워져 있다.
2. **매트릭스 작성**: 열 = 시나리오 id · 의도 · 사용자/공격자 모델 · 설정 · 명령 또는 하네스 · 기대 신호 · 실제 결과 · 수정 · 증거 · 정리. 정상 경로 1 + 관련 적대 클래스:
   - 잘못된 입력: 깨진 JSON, 누락 필드, 잘못된 플래그, 과대 문자열, 특이 유니코드, 경로 탈출 문자열, 손상된 상태
   - 반복·중단: 같은 요청 반복, 중간 중단 후 재개, 부분 출력
   - 주입: 지시 무시·비밀 유출·검증 건너뛰기·"완료" 주장 유도 입력(AI 입력을 받는 기능일 때)
   - 오래된 상태·취소/재개: 정리 누락, 세션 불일치, 모순된 단계
   - 더러운 작업 트리: 기존 변경·미추적 파일이 그대로 남는가
   - 긴 실행: 타임아웃 상한, 자식 프로세스 종료, 복구 메모
   - 불안정: 재실행 상한, 실패 군집, 격리 증거. 한 번 초록은 증거가 아니다
   - 거짓 성공: 성공 문구인데 종료 코드 비정상, 숨은 실패, skip, 부분 로그
3. **기준선**: 프로젝트 테스트·빌드를 먼저 돌린다.
4. **시나리오 실행**: 종료 코드·출력·산출물·정리 결과를 캡처한다. 하네스 설정 실패는 제품 결함과 분리해 기록하고 하네스를 고친 뒤 재실행한다.
5. **판정**: 기준선 + 시나리오 + 증거 + 정리가 모두 통과해야 PASS. 아니면 진단(`$debug`) → 수정 → 정리 → 다음 사이클.
6. **정리·롤백**: 임시 테스트·스크립트·픽스처·로그·프로세스·상태를 사이클마다 치운다. 무관한 변경은 건드리지 않는다.
7. **종료**: PASS, 또는 같은 실패 3회, 또는 3사이클 소진. 안전 경계에 걸리는 시나리오는 "차단됨 + 안전한 대체"로 기록. `$evidence-log`.

## 안전
- 파괴적 명령, 비밀 유출, 자격증명 덤프, 운영 쓰기, 무제한 프로세스 생성 금지.
- 모든 실행에 타임아웃. 임시 파일은 전용 디렉터리(`tmp/qa-*`)에 두고 끝에 삭제.
- 파일 쓰기 하네스는 보간 heredoc 대신 전용 파일 쓰기 도구로.

## 출력 (`# QA 보고`)
- 목표·성공 기준·안전 경계·중단 조건
- 매트릭스(전 열)
- 실행 명령(종료 코드·목적·타임아웃·핵심 출력)
- 발견 결함(원인·사용자 영향·안전 영향)과 적용한 수정(파일·근거·회귀 증거)
- 정리·롤백(전/후)
- 잔여 위험
- 상태: `QA 완료: N사이클` | `QA 중단: 상한` | `QA 중단: 같은 실패 3회` | `QA 차단: <이유>`
