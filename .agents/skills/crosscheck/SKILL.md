# crosscheck — 다른 모델의 독립 교차검증

내부 리뷰가 "머지 가능"이라 한 고위험 변경을 다른 모델이 두 번 뒤집은 적이 있다. 그래서 되돌리기 어려운 변경은 작성 모델과 다른 모델의 독립 리뷰를 거친다.

## 언제 필수인가
- 파일·데이터·프로세스를 삭제·종료·덮어쓰는 코드
- 동시성·잠금·재시도 루프
- 인증·권한·비밀값·입력 경계
- 스키마·마이그레이션·공개 API 변경
- 내부 리뷰와 작성자의 의견이 갈릴 때

## 절차
1. **리뷰어 선택**: 작성 모델과 **다른 모델**의 리뷰어를 쓴다. kit의 교차 리뷰어는 `cofa-reviewer-terra`다(모델은 그 TOML을 따른다). 모델을 프롬프트나 `-m`으로 바꾸지 않는다. 설정은 TOML이 단일 진실원이다. **고위험 변경은 `cofa-reviewer` 리뷰가 필수**이고, 교차 리뷰는 추가 시각이지 대체가 아니다. 완료 기준: 두 리뷰어 이름이 기록돼 있다.
2. **입력 구성**: (a) 요구사항 원문, (b) 변경본(diff), (c) 반례 후보 2~3개(깨질 것 같은 입력·상태·순서), (d) 불변식(절대 깨지면 안 되는 조건) 목록. **작성자의 결론·요약·"문제 없음" 판단은 넣지 않는다.** 이유: 결론을 받은 리뷰어는 확인하는 쪽으로 기운다.
3. **실행**: 등록된 커스텀 에이전트 `cofa-reviewer-terra`를 spawn해 2의 입력과 함께 반론 중심으로 지시한다: "이 변경이 불변식을 깨는 시나리오를 찾아라. 못 찾으면 어디까지 확인했는지 써라." 고위험이면 `cofa-reviewer`도 같은 입력으로 별도 spawn한다(두 리뷰어는 서로의 결과를 보지 않는다).
4. **라운드**: 지적 → 수정(`$execute`) → 같은 입력으로 재리뷰. 최대 3라운드. 라운드마다 지적·반영·잔여를 기록한다.
5. **종결 조건**: 확신도 높음의 높음·중간 결함 0건, 또는 남은 지적이 "알려진 한계"로 사용자 승인을 받음.

## 규칙
- 리뷰어가 "확인 불가"만 내놓으면 입력이 부족한 것이다. 반례·불변식을 더 주고 다시 요청한다.
- 리뷰 결과를 작성자가 재해석해 축소하지 않는다. 원문을 기록에 남긴다.
- 라운드 기록은 `templates/review-round.md` 형식으로 `docs/decision-log.md`에.

## 출력
- 리뷰 모델, 라운드 수
- 라운드별 지적(심각도)과 반영
- 종결 조건 충족 여부
- 알려진 한계(사용자 승인 포함)
