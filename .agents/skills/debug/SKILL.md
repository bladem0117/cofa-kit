# debug — 근본 원인 추적

OMC `debugger`(최소 수정·3회 회로차단기)와 `tracer`(경쟁 가설·증거 강도·반증 탐색)를 합쳤다. 증상에 널 체크를 덧대는 대신 "왜 undefined인가"를 답한다.

## 절차
1. **재현**: 가장 작은 재현 절차를 만들고 실행한다. 재현이 안 되면 조건(입력·순서·환경)을 먼저 찾는다. 완료 기준: 재현 명령과 결과가 있다.
2. **관찰 기록**: 해석 없이 관찰만 적는다. 오류 메시지는 **끝까지** 읽고 그대로 인용한다. 스택의 위치, 종료 코드, 로그 시각.
3. **증거 수집(병렬)**: 오류 위치의 실제 코드, 최근 변경(`git log -p`·`git blame`), 같은 패턴의 동작하는 코드, 관련 테스트. 넓은 검색은 `cofa-explorer`에 위임.
4. **경쟁 가설 ≥2**: 서로 다른 틀(코드 경로 / 설정·환경 / 측정 오류 / 순서·동시성 / 가정 불일치)로 가설을 세운다. 표: 가설 · 찬성 증거 · 반대 증거/공백 · 이 가설이 참이면 보여야 할 관찰 · 구별 프로브.
5. **증거 강도로 순위**: 재현·직접 실험 > 일차 산출물(로그·추적·git 이력·파일:줄 동작) > 독립 출처의 수렴 > 단일 경로 추론 > 정황(이름·시간 근접·스택 위치) > 직관. 약한 증거만 있는 가설은 강한 반대 증거 앞에서 내린다. **선호 가설의 반증을 먼저 찾는다.**
6. **구별 프로브 실행**: 상위 두 가설을 가르는 프로브 하나를 실행한다. 같은 종류의 지지 증거를 더 모으는 프로브는 고르지 않는다.
7. **원인 확정 → 수정 1개**: 변경은 하나만, 최소 diff. 수정이 맞다면 통과할 테스트를 **먼저 예측**하고 실행한다. 같은 패턴이 다른 곳에도 있는지 확인한다.
8. **회로차단기**: 가설 3개가 틀리면 멈춘다. 버그가 다른 곳에 있는지 의심하고, 증상·시도·남은 가설을 정리해 `cofa-architect`에 넘긴다.
9. **회귀 테스트** 추가(`$test-strategy`), `$evidence-log` 기록(가설 → 수정 → 재검증 → 한계).

## 빌드·타입 오류 변형
1. 매니페스트로 언어·도구 확인. 2. 오류 **전부** 수집(빌드·타입체크 명령). 3. 분류: 타입 추론 / 정의 누락 / import·export / 설정. 4. 하나씩 최소 수정 후 해당 파일 재검사. 5. "X/Y 해결" 진행 보고. 6. 최종 빌드 종료 코드 0.

## 규칙
- 한 번에 가설 하나. 수정을 묶지 않는다.
- "~인 것 같다", "아마"는 발견이 아니다.
- 수정하면서 리팩터링·이름 변경·최적화를 하지 않는다. 논리 흐름은 버그를 직접 고칠 때만 바꾼다.
- 상관·근접·스택 순서를 증거 없이 인과로 쓰지 않는다.
- 두 가설이 모두 사실에 맞으면 둘 다 남기고, 가르는 미확인 요소를 이름 짓는다.

## 출력
- 재현 절차와 결과
- 가설 표(순위·찬성·반대·프로브)
- 근본 원인(파일:줄)과 메커니즘 한 줄
- 적용한 수정과 증명 명령 결과
- 같은 패턴 점검 결과
- 잔여 불확실성과 다음 프로브
