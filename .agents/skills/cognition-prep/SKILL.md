# cognition-prep — 확인 문제 대비

Cofa-Probe는 빌드가 끝나면 **AI 없이** 문항당 3분, 5문항(+사후 재심문)을 사람이 타이핑한다. 문항은 Probe가 산출물을 읽고 즉석 생성하며("특정 부분을 왜 그렇게 만들었나, 장애 대응"), 채점은 미리 만든 모범답안과 3단계 구조를 대조한다. 2026-07 참가자 후기: **Cognition은 전원이 가장 낮았던 축**이다. 여기서 점수가 갈린다.

## 언제 쓰나
- 빌드 마감 20~30분 전(`$cleanup` 뒤, `$submission-check` 전). **준비·연습 전용**이다.
- 사후 재심문이 오면 **AI 사용이 명시적으로 허용되는지 먼저 확인**한다. 허용 명시가 없으면 이 스킬을 쓰지 않고, 이미 만든 연습 자료만 사람이 참고한다.

## 금지
- 실제 확인 문제 시간(무AI)에는 Codex를 닫는다. 이 스킬로 실제 문항의 답을 만들지 않는다. 규정 위반이며 사용 이력은 검토 대상이다.

## 절차
1. **산출물 훑기**: `git log --oneline`, 변경 파일 목록, `docs/agreement.md`, `docs/decision-log.md`, `docs/onboard.md`를 읽는다. 사람이 설명해야 할 "결정 지점"을 8~12개 뽑는다(구조 선택, 데이터 흐름, 외부 의존, 오류 처리, 테스트 범위, 포기한 것). 완료 기준: 결정 지점 목록.
2. **예상 질문 생성**: 결정 지점마다 세 틀로 질문을 만든다 — "왜 이렇게 만들었나(대안은)", "X가 실패하면 어떻게 되나·어떻게 알아채나", "이 부분의 가장 큰 약점은". 총 10~15문항.
3. **모범답안 초안**: 각 문항에 **3단계**로 쓴다. ① 구체적 약점·결정 근거(파일·함수·숫자) → ② 파급 위험(무엇이 어떻게 깨지나, 누구에게) → ③ 다음 검증·개선 계획(명령·테스트·일정). 각 답은 3분 타이핑 분량(5~7문장)으로 맞춘다.
4. **사람 검수**: 초안을 `docs/cognition-prep.md`에 쓰고 사람이 읽는다. 사람이 동의하지 않는 답은 사람의 말로 고친다(그 사실은 `docs/submission-notes.md` 2절). 답할 수 없는 문항이 있으면 그게 가장 약한 지점이다 → 시간이 남으면 그 부분을 보강하거나, 솔직히 "한계"로 답을 준비한다.
5. **암기 카드**: 파일 맨 위에 결정 지점 8~12개를 한 줄씩(이름 · 왜 · 약점 · 다음) 정리한다. 확인 문제 시간에는 이 파일을 볼 수 없다고 가정하고, 사람이 직전에 2분간 읽는다.

## 규칙
- 답은 1인칭, 사실 기반. 하지 않은 검증을 했다고 쓰지 않는다. "확인하지 못했다, 다음에 X로 확인하겠다"가 거짓 확신보다 점수가 높다.
- AI 용어보다 도메인·사용자 영향으로 말한다("리트라이 추가"보다 "결제 중복 2건이 날 수 있어 멱등 키를 넣었다").
- 질문에 없는 자랑은 쓰지 않는다. 약점 → 위험 → 계획 순서를 지킨다.

## 출력
- `docs/cognition-prep.md`: 암기 카드 + 문항별 3단계 초안
- 답하지 못한 문항(가장 약한 지점) 목록
