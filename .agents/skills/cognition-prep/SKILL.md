# cognition-prep — 확인 문제 대비

Cofa-Probe는 빌드가 끝나면 **AI 없이** 약 25분 동안(2026-10-31 실전 실측. 코파톤 후기는 3분×5문항, +사후 재심문) 산출물에 대한 질문에 사람이 타이핑한다. 문항은 Probe가 산출물을 읽고 즉석 생성하며("특정 부분을 왜 그렇게 만들었나, 장애 대응"), 채점은 미리 만든 모범답안과 3단계 구조를 대조한다. 2026-07 참가자 후기: **Cognition은 전원이 가장 낮았던 축**이다. 여기서 점수가 갈린다. 평가자 발언(2026-10 팟캐스트): 문항은 산출물에서 생성되며 "어떤 패턴을 왜 썼고, 이 프로덕트 라이프사이클에서 왜 유효한가"를 설명할 수 있는지, AI의 과설계를 통제했는지를 본다. 예: 읽기 전용 API 뒤의 DB에 쓰기 가드를 촘촘히 넣은 것은 "범용적으로 잘 설계됐지만 우리 요구에 맞춘 것은 아니다".

## 언제 쓰나
- 빌드 마감 15~20분 전(`$cleanup` 뒤, `$submission-check` 전). **준비·연습 전용**이다.
- 사후 재심문이 오면 **AI 사용이 명시적으로 허용되는지 먼저 확인**한다. 허용 명시가 없으면 이 스킬을 쓰지 않고, 이미 만든 연습 자료만 사람이 참고한다.

## 금지
- 실제 확인 문제 시간(무AI)에는 Codex를 닫는다. 이 스킬로 실제 문항의 답을 만들지 않는다. 규정 위반이며 사용 이력은 검토 대상이다.

## 절차
1. **산출물 훑기**: `git log --oneline`, 변경 파일 목록, `docs/agreement.md`, `docs/decision-log.md`, `docs/onboard.md`, `docs/plans/*.md`("모형"·"방법 선택"·절단된 행), `docs/verification.md`(실측 숫자), `docs/submission-notes.md` 2절을 읽는다. 사람이 설명해야 할 "결정 지점"을 8~12개 뽑는다(기준·가정 — 합의문 3-1절과 가정 목록, 방법 수준, 기술 선택, 구조 선택, 데이터 흐름, 외부 의존, 오류 처리, 테스트 범위, 포기한 것, 파라미터 기본값과 그 출처(실무자 인용·데이터 통계·내 가정), 절단한 요구와 이유, 유지보수 주체와 변경 경로(코드 없이 바꾸는 것·코드가 필요한 것), 다음 방향(단기·중기와 그 이유), 가져온 하네스·스킬에서 쓴 것과 바꾼 것). 완료 기준: 결정 지점 목록.
2. **예상 질문 생성**: 결정 지점마다 세 틀로 질문을 만든다 — "왜 이렇게 만들었나(대안은)", "X가 실패하면 어떻게 되나·어떻게 알아채나", "이 부분의 가장 큰 약점은", "이 설계는 범용 모범사례인가, 우리 요구에 맞춘 것인가 — 일부러 하지 않은 것은", "더 강한 방법(정확해·완전 자동화·실시간) 대신 왜 이 수준인가". 총 10~15문항.
3. **모범답안 초안**: 각 문항에 **결정 이유 + 3단계**로 쓴다. ⓪ 무엇을 택했고 왜(목적함수·제약·규모 용어로. "변수가 정의 안 됐다"처럼 입력 부족으로 들리는 말 대신 "대수 상한과 허용 시간이 합의되지 않았다") → ① 그 선택의 약점(파일·함수·숫자) → ② 파급 위험(무엇이 어떻게 깨지나, 누구에게) → ③ 다음 검증·개선 계획(명령·테스트·일정). 각 답은 3분 타이핑 분량(5~7문장). 문항당 시간이 더 있으면 ③을 명령·숫자로 구체화한다. 2026-10-31 실전: ⓪만 말한 답은 절반이다.
4. **사람 검수**: 초안을 `docs/cognition-prep.md`에 쓰고 사람이 읽는다. 사람이 동의하지 않는 답은 사람의 말로 고친다(그 사실은 `docs/submission-notes.md` 2절). 답할 수 없는 문항이 있으면 그게 가장 약한 지점이다 → 시간이 남으면 그 부분을 보강하거나, 솔직히 "한계"로 답을 준비한다.
5. **암기 카드**: 파일 맨 위에 결정 지점 8~12개를 한 줄씩(이름 · 왜 · 약점 · 다음) 정리한다. 그 아래에 핵심 숫자 5개(데이터 규모, 현재값→달성값, 갭·오차 %, 실행 시간, 주요 파라미터 기본값)를 적는다. 확인 문제 시간에는 이 파일을 볼 수 없다고 가정하고, 사람이 직전에 2분간 읽는다.

## 규칙
- 답은 1인칭, 사실 기반. 하지 않은 검증을 했다고 쓰지 않는다. "확인하지 못했다, 다음에 X로 확인하겠다"가 거짓 확신보다 점수가 높다.
- AI 용어보다 도메인·사용자 영향으로 말한다("리트라이 추가"보다 "결제 중복 2건이 날 수 있어 멱등 키를 넣었다").
- 질문에 없는 자랑은 쓰지 않는다. 약점 → 위험 → 계획 순서를 지킨다.
- "왜"의 답은 **우리 요구사항 기준**으로 쓴다. "모범사례라서"만으로는 부족하다. 뺀 것(거부한 과설계)도 결정이다 — `docs/submission-notes.md` 2절에서 가져온다.

## 출력
- `docs/cognition-prep.md`: 암기 카드 + 문항별 3단계 초안
- 답하지 못한 문항(가장 약한 지점) 목록
