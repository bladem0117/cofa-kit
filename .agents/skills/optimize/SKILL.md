# optimize — 제약 최적화의 모형화와 방법 선택

실전 두 과제(경로 구성, 장비 배치·선택)가 모두 "예산·제약 안에서 기준을 직접 세우는 조합 최적화 + 실무자 webUI"였다. 이 스킬은 **도메인 답이 아니라 뼈대**를 준다: 모형 세 줄 → 사다리에서 사용자가 고름 → 지표와 검증 계획 → 확인 문제 답 틀. 코드는 쓰지 않는다(`$execute`가 쓴다).

## 언제 쓰나
- `$plan` 초안에 판정·배정·배치·스케줄·경로·선택 로직이 있고 "방법 선택" 행이 비어 있을 때. `$stakeholder-interview` 2차 왕복 **앞**에 한다 — 안을 만들려면 모형이 먼저 있어야 한다.
- 분류·예측·이상감지·원인 분석 같은 통계 문제는 대상이 아니다(`docs/domain-fab.md` 유형 표의 "분석형"). 그 문서의 "최적화가 아닌 유형의 뼈대" 절로 계획 "모형"·"방법 선택" 행을 채우고 2차 왕복으로 간다.

## 절차
1. **모형 세 줄**: 결정변수(무엇을 고르나 — 후보 위치×종류×방향, 로트→설비, 순서), 목적(최대·최소 하나. 둘이면 가중합 또는 한쪽을 제약으로 내림), 제약(예산·용량·필수·금지·시간창). 숫자는 `$onboard` 데이터 지도에서 가져온다. 완료 기준: 계획 파일 "모형" 절에 세 줄이 있다.
2. **문제군 이름**: 배정(assignment) / 커버·선택(set cover, 예산 제약 최대 커버) / 순서·일정(job shop, 구간 스케줄링) / 경로(VRP) / 입지(facility location) / 묶기(bin packing) / 배합·구성(diet·blending LP — 영양·예산 범위 안 비용 최소, 다양성·반복 상한이 붙으면 MILP). 교과서 이름을 적는다 — "알고 골랐다"의 증거다. 위치·방향·시간 같은 연속 공간은 **격자·후보 집합으로 이산화**하고 해상도를 파라미터로 둔다.
3. **사다리** — 아래로 갈수록 품질↑ 구현 비용↑. 규모·남은 시간·기준 확정 여부로 단을 고르고 **사용자가 결정**한다.

| 단 | 방법 | 언제 | 보장 |
|---|---|---|---|
| 0 | 규칙 하나(정렬·우선순위) | 기준 미확정, 15분 미만 | 없음. 기준선 |
| 1 | 그리디(비용당 효과) + 교환·2-opt 개선 | 실규모, 반복 실행 | 실행 가능해. 커버류는 단위 비용 기준 1−1/e≈63% 하한(예산 제약은 더 낮음) |
| 2 | 정확해 MILP·CP-SAT·배정(linear_sum_assignment) | 후보 수천 이하, 기준 확정 | 최적 또는 증명된 갭 |
| 3 | **1의 해를 초기해(warm start)로 넣고 2를 시간 상한(30~120초)으로 돌림** | 실규모에서 품질까지 | 항상 1 이상. 시간 내 갭 보고 |

   기본 권장은 **3**이다(2026-11-04 실전에서 통과한 구성). 1을 먼저 끝내 화면·검증을 돌리고 2를 얹는다. 2가 시간 안에 못 끝나도 1의 해가 남는다.
4. **파라미터 외부화**: 예산, 카탈로그(종류별 비용·성능), 해상도, 가중치, 시간 상한을 설정 파일 또는 UI 입력으로. 코어는 결정론(같은 입력→같은 출력)이고 재실행 가능하다. "실무진이 실행한다"의 실체가 이것이다.
5. **품질 지표**: 목적값, 제약 충족(필수 100%·예산 이하), 상한(LP 완화·이론 하한·소규모 정확해)과 갭 %, 실행 시간. webUI 결과 화면에 **갭을 함께 표시**한다 — "왜 완전 최적화가 아닌가"의 답이 화면에 있게.
6. **검증 계획**(`$verify`에 넘김): (a) 독립 코드로 해의 제약·목적 재계산 (b) 소규모 인스턴스(후보 ≤ 20)에서 브루트포스 또는 정확해와 비교 (c) 파라미터 극단(예산 0·무한, 해상도 2배)에서 퇴화 없이 동작 (d) 같은 입력 재실행 시 동일 출력.
7. **기록**: 계획 "방법 선택" 행(선택·이유·보장·지표), `docs/submission-notes.md` 2절에 "방법 수준은 사용자 결정" 한 행, `$evidence-log` 엔트리. 2차 왕복용 2~3안(목적·제약·파라미터 차이)은 1·4단계에서 그대로 나온다.

## 도구 — 설치 확인 먼저, pip·네트워크 불가를 가정
`python -c "import scipy; print(scipy.__version__)"` 식으로 scipy·ortools·pulp를 확인한다. scipy만 있어도 `scipy.optimize.milp`(HiGHS, time_limit 옵션)와 `linear_sum_assignment`로 2·3단이 된다. 아무것도 없으면 1단 + 표준 라이브러리 브루트포스(후보 ≤ 20)로 보장을 보인다. 참조 저장소와 읽는 규칙은 `docs/reference-repos.md`.

## Q&A 답 틀(`$cognition-prep`에 넘김)
"문제는 <문제군>이고 NP-hard다(이산화 자체도 근사). 그래서 <단>을 택했다. 보장은 <…>, 실측 갭은 상한 대비 N%다. 약점은 <해상도·가정>, 파급은 <갭이 커지는 입력>, 다음 검증은 <해상도 2배·시간 상한 2배 재실행>."

## 규칙
- 방법 선택을 AI가 대신하지 않는다. 사다리와 근거만 주고 사용자의 선택을 기록한다.
- 도메인 해법 코드를 미리 가져오지 않는다. 문제군 이름과 뼈대만.
- 상한 없는 "최적"이라는 말을 쓰지 않는다. 갭을 모르면 "갭 미측정"이라고 적는다.

## 출력
- 계획 파일 "모형" 절(세 줄 + 문제군 + 이산화 해상도)과 "방법 선택" 행(사용자 결정)
- 파라미터 목록, 품질 지표, 검증 계획 4항
- 2차 왕복용 2~3안(한 줄씩)
- 다음 행동: `$stakeholder-interview` 2차 왕복 → `$execute`(1단 뼈대 먼저)
