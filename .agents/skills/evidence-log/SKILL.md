# evidence-log — 결정·증거 기록

로그의 양이 아니라 **왜 그렇게 했고, 무엇으로 확인했고, 무엇이 남았는지**가 평가된다. 기록은 사후 질문에 로그만 보고 답할 수 있을 때 완성이다.

## 언제 쓰나
- `$plan`·`$execute`·`$review`·`$verify`·`$crosscheck` 각 단계가 끝났을 때
- 자명하지 않은 결정(모델 선택, 범위 축소, 우회, 한계 수용)을 했을 때
- 실패했을 때(실패도 기록 대상이다. 복구 과정이 Cognition 점수다)

## 절차
1. `docs/decision-log.md` 맨 아래에 새 엔트리를 추가한다. 형식은 아래 그대로. 완료 기준: 네 칸(가설/조치/재검증/한계)이 모두 채워져 있거나 "해당 없음"으로 명시돼 있다.
2. 증거 칸에는 **명령·종료 코드·출력 요약**을 쓴다. "테스트 통과"만 쓰지 않는다. 어떤 테스트가 몇 개 통과했는지.
3. 모델·토큰·시간을 알 수 있으면 적는다(추정이면 "추정" 표시). 몰라도 엔트리를 미루지 않는다.
4. 이전 엔트리를 수정하지 않는다. 바뀌었으면 새 엔트리로 "이전 결정 X를 Y로 변경, 이유 Z".

## 엔트리 형식

```
### [번호] [단계] 제목 — YYYY-MM-DD HH:MM
- 분류/모델: Trivial|Scoped|Complex / 사용 모델(effort)
- 가설·의도: 무엇을 왜 하려 했나(목표·제약 한 줄)
- 조치: 무엇을 바꿨나(파일, 요지) 또는 무엇을 물었나
- 재검증: `명령` → 결과(종료 코드, 통과/실패 수, 핵심 출력 한 줄)
- 한계·잔여: 확인 못 한 것, 받아들인 위험, 다음 행동
- 비용(선택): 토큰/시간, 추정 여부
```

## 규칙
- 사실과 추정을 구분한다. 추정에는 "추정"을 붙인다.
- 비밀값·개인정보는 기록하지 않는다. 명령 출력에 섞였으면 `[REDACTED]`.
- 한 엔트리는 화면 반 쪽을 넘지 않는다. 길어지면 파일을 가리키는 포인터로.

## 출력
- 추가한 엔트리 번호와 제목
- 다음 행동 한 줄
