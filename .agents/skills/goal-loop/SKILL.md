# goal-loop — 상한 있는 자율 루프

OMC의 ralph·ultragoal이 하던 "완료까지 계속"을 Codex 네이티브 `/goal`로 한다. 차이는 하나다: **상한 없는 루프는 만들지 않는다.** 루프 사고(세션 3개, 수백 콜, 산출물 0)의 재발 방지가 이 스킬의 존재 이유다.

## 언제 쓰나
- 단계가 많고 한 턴에 끝나지 않는 과제(마이그레이션, 다중 모듈 기능, 반복 수정·검증)
- 사용자가 "끝날 때까지", "알아서 계속"을 요청했을 때

## 언제 쓰지 않나
- 한 번의 집중 패스로 끝나는 과제. 조정 비용이 결과를 넘어선다.
- 완료 기준을 문장으로 쓸 수 없는 과제. 먼저 `$plan`으로 기준을 만든다.

## 절차
1. **목표 문장 작성**(아래 형식). 완료 기준은 "명령 X → 관찰 Y"로 쓴다. 완료 기준: 네 요소(기준·예산·반복 상한·중단 조건)가 모두 있다.
2. **예산 결정**: 과제 크기별 기본값 — Scoped 300k 토큰·반복 10회, Complex 1M 토큰·반복 25회. 근거는 `docs/decision-log.md`에 한 줄.
3. **`/goal` 시작**: 목표 문장 그대로 등록한다. `[features] goals = true`는 `.codex/config.toml`에 이미 있다.
4. **매 반복**: (a) 현재 변경본에 대해 가장 좁은 검증을 실행, (b) 결과를 `$evidence-log`에 한 줄, (c) 같은 실패가 3회면 멈춤.
5. **완료 감사**: 완료 기준의 명령을 **지금** 다시 실행해 결과를 인용한다. 이전 턴의 통과, 요약문, "테스트가 있다"는 증거가 아니다. 통과하면 `$verify`로 최종 판정을 받고 종료한다.
6. **중단 시**: 예산 80% 도달, 반복 상한, 같은 실패 3회, 범위 이탈 중 하나라도 해당하면 멈추고 상태(완료된 것·남은 것·막힌 이유)를 기록한 뒤 사용자에게 넘긴다.

## 목표 문장 형식

```
목표: <한 문장>
완료 기준:
  1. `명령` → 기대 관찰
  2. ...
예산: 토큰 N / 반복 M회 / 시간 T분
중단 조건: 같은 실패 3회, 예산 80%, 범위 이탈(계획에 없는 파일 수정 필요), 사용자 입력 필요
증거 규칙: 완료 판단은 현재 diff에 대해 지금 실행한 명령의 종료 코드·출력으로만
```

## 규칙
- 목표를 중간에 넓히지 않는다. 넓어져야 하면 멈추고 새 목표로 다시 시작한다(goal drift 방지).
- 원래 목표 문장을 반복 5회마다 다시 읽고 현재 작업이 그 안에 있는지 확인한다.
- 긴 문맥에서 recall이 떨어지므로 상태는 대화가 아니라 `docs/notepad.md`에 외부화한다.

## 출력
- 등록한 목표 문장
- 반복별 한 줄 기록 위치
- 종료 사유(완료/중단)와 최종 검증 결과
