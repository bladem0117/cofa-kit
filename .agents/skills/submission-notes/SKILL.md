# submission-notes — 제출용 사람 기록

평가 환경은 마지막에 사람이 직접 "내가 구현한 것"과 "AI 제안 중 내가 수정한 것"을 쓰게 한다. 이 스킬은 그 답을 **작업 중에 미리 쌓아** 제출 직전 5분 안에 다듬을 수 있게 한다. `decision-log`가 AI의 결정 기록이라면, 이 파일은 **사람의 개입 기록**이다.

## 언제 쓰나
- 사용자가 AI 제안(계획·구현·리뷰 지적·설계)을 **수정·거부·대체**했을 때 → 즉시 2절 한 행
- `$execute`가 단위 하나를 끝냈을 때 → 1절 한 행
- `$verify`·`$qa-adversarial` 결과가 나왔을 때 → 3절 한 행
- 제출 전 `$submission-check` 직전 → 전체 정리(아래 절차 5~7)

## 절차
1. **파일 확인**: `docs/submission-notes.md`가 없으면 kit 템플릿으로 만든다. 완료 기준: 6개 절이 있다.
2. **1절(구현)**: 단위마다 "변경 한 줄 · 파일 · 왜(사용자 요구 기준) · 검증 명령→결과 · decision-log 번호". AI가 한 일이라도 사용자가 지시·승인한 것은 사용자의 구현으로 적는다. 사용자가 손으로 고친 부분은 "(직접 수정)"을 붙인다.
3. **2절(수정)**: 사용자가 "그건 빼", "이렇게 바꿔", "그 지적은 받아들이지 않겠다"라고 했을 때 — AI 제안 원문 요지 · 결정(수정/거부/대체/승인) · 바꾼 내용 · 이유. 사용자가 이유를 말하지 않았으면 "[이유 확인 필요]"로 남기고 다음 턴에 한 번만 묻는다.
4. **3절(검증)**: 무엇을 · 명령 · 결과 · 누가(리더/cofa-verifier/사람 수동).
5. **정리(제출 전)**: 1~3절 중복 행을 합치고, 4절(한계·남은 일)을 `decision-log` 최근 엔트리의 "한계·잔여"에서 모아 적는다. 5절에 참고한 공개 저장소·문서를 적는다.
6. **최종 문장 초안**: 6절에 두 문장을 쓴다. "내가 구현한 것: (1절을 3~5개 항목으로)" / "AI 제안 중 내가 수정한 것: (2절을 항목별로, 이유 포함)". 사람이 읽고 고칠 수 있게 1인칭으로.
7. 사용자에게 6절을 보여 주고 "이대로 제출할지, 고칠지"를 묻는다. 이 질문은 블로킹이 아니라 제출 직전의 확인이다.

## 규칙
- 사람이 하지 않은 결정을 사람이 한 것처럼 쓰지 않는다. AI가 혼자 결정한 것은 `decision-log`에만.
- 비밀값·개인정보 금지. 명령·경로·오류 문구는 그대로.
- 파일 쓰기는 한 번에. 행 하나 추가하려고 파일을 다시 읽지 않는다.

## 출력
- 추가·정리한 절과 행 수
- 6절 초안 전문
- "[이유 확인 필요]" 남은 항목
