# cleanup — 변경 파일 정리 (동작 보존)

OMC `ai-slop-cleaner`·`code-simplifier`의 회귀 안전 절차를 변경 파일 범위로 줄였다. 심사자는 코드 구조를 보고, AI가 남긴 군더더기는 바로 눈에 띈다.

## 언제 쓰나
- `$execute`·`$debug` 뒤, `$verify` 전후, 제출 전
- 사용자가 정리·단순화·deslop을 요구할 때

## 언제 쓰지 않나
- 새 기능 추가나 설계 변경(→ `$execute`, `$design-review`)
- 동작을 테스트로 보호할 수 없을 때 → 먼저 `$test-strategy`

## 절차
1. **범위 고정**: `git diff --name-only`로 이번 작업의 변경 파일만. 범위를 넓히지 않는다. 완료 기준: 파일 목록이 적혀 있다.
2. **동작 고정**: 관련 테스트를 돌려 기준선을 적는다. 커버리지가 없으면 바꿀 함수에 회귀 테스트를 먼저 추가한다.
3. **냄새 분류 후 계획**(편집 전에 쓴다): 죽은 코드 · 디버그 출력(console.log/print) · 중복 헬퍼(저장소에 이미 있는 것) · 단일 사용 래퍼/추상화 · 코드를 되풀이하는 주석 · 저장소 관례와 다른 이름 · 남은 TODO/skip · 불필요한 의존성. 각각 파일:줄과 조치(삭제/치환/이름 변경).
4. **한 냄새씩 한 패스**: 삭제 우선. 패스마다 테스트를 돌린다. 실패하면 그 패스만 되돌린다.
5. **분리 승인**: 변경이 크거나 공용 코드에 닿으면 정리 작성자와 다른 에이전트가 `$review`로 본다. 같은 패스에서 쓰고 승인하지 않는다.
6. **보고**: 냄새 표(종류·파일·조치), 전/후 테스트 결과, 삭제·추가 줄 수. `$evidence-log`.

## 규칙
- 동작 변경 금지(사용자가 명시 요청한 경우만 예외). 공개 인터페이스 시그니처 유지.
- 새 의존성 금지. 기존 유틸·패턴 재사용.
- diff는 작고 되돌릴 수 있게. 리네임 폭풍 금지.
- 정리가 설계 문제를 드러내면 고치지 말고 `docs/decision-log.md`에 "후속 후보"로 적는다.

## 출력
- 대상 파일
- 냄새 표(종류 · 파일:줄 · 조치)
- 기준선/최종 테스트 결과(명령·통과 수)
- 줄 수 변화(−삭제/+추가)
- 남긴 것과 이유
