# verify — 검증

"동작할 것이다"를 "이 명령이 이 결과를 냈다"로 바꾼다.

## 절차
1. **증명할 것 정의**: 수용 기준을 한 줄씩 적는다. 계획이 있으면 계획의 수용 기준을 그대로 쓴다. 완료 기준: 기준 목록이 있다.
2. **위임 또는 직접**: Scoped 이상이면 `cofa-verifier` 서브에이전트에 기준 목록·변경 파일·실행 가능한 명령 후보를 주고 판정을 받는다. Trivial이면 리더가 직접 가장 좁은 검증 명령을 돌린다.
3. **증거 순서**: 기존 테스트 → 빌드/타입체크 → 기준을 직접 찌르는 명령 → 수동 관찰. 가능한 앞 단계에서 끝낸다.
4. **연결**: 각 기준에 VERIFIED/PARTIAL/MISSING과 증거(명령·종료 코드·출력 요약)를 붙인다. 변경 전 결과, 기억 속 결과, 요약문은 증거가 아니다.
5. **판정식**: 기준별 상태는 PASS(증거로 충족) / FAIL(실행 결과가 기준 위반) / INCOMPLETE(미실행·부분 증거) / N/A(실행 환경 문제로 측정 불가, 이유 명시) 중 하나. 전체 판정은 **필수 기준 전부 PASS일 때만 PASS**, FAIL이 하나라도 있으면 FAIL, 그 외는 INCOMPLETE. 환경 실패(N/A)는 FAIL과 섞지 않고 따로 적는다. 결과를 `docs/verification.md`에 "검증 대상(커밋/변경본 ID) · 기준별 표 · 전체 판정"으로 저장한다(재검증 시 덮어쓰지 말고 아래에 새 블록).
6. **기록**: `$evidence-log`에 판정과 명령을 남기고, `docs/submission-notes.md` 3절에 "무엇을 · 명령 · 결과 · 누가(리더/cofa-verifier/사람)" 한 행을 추가한다(`$submission-notes`).

## 고위험 변경의 하드 읽기 전용 검증
서브에이전트의 "읽기 전용"은 지시문 수준이다(Codex 커스텀 에이전트는 샌드박스를 부모에게서 상속한다). 삭제·프로세스 제어·마이그레이션·보안 변경처럼 verifier가 코드를 건드리면 안 되는 경우에는 검증을 **별도 프로세스**로 돌려 샌드박스 자체를 읽기 전용으로 만든다.

```bash
codex exec -s read-only -C "$PWD" --skip-git-repo-check \
  "verifier 역할로 다음 수용 기준을 검증하라. 파일을 수정하지 말고 명령 결과만 인용하라: <기준 목록>"
```

- 중첩 실행이 샌드박스·네트워크 제한으로 막히면(환경 의존) 지시문 verifier로 돌아가되, 리더가 핵심 명령 2~3개를 **직접 다시 실행**해 결과를 대조한다.
- 고위험 변경은 "검증이 충분했는가"를 별도로 묻는다. `cofa-verifier`의 증거 표를 리더가 다시 읽고, 수용 기준이 빠짐없이 덮였는지·좁은 체크가 끝단 동작을 대신하지 않았는지 판단한다. 부족하면 추가 검증을 지시하고 PASS를 보류한다.
- 어느 경로를 썼는지, 충분성 판단을 누가 했는지 `$evidence-log`에 적는다.

## 금지어
완료 보고에 "should, probably, seems, 아마, ~일 것이다, ~인 것 같다"를 쓰지 않는다. 보이면 그 주장은 미검증으로 되돌린다.

## 출력
- 판정과 확신도
- 증거 표(확인 | 결과 | 명령 | 출력 요약)
- 수용 기준 표(기준 | 상태 | 증거)
- 공백과 잔여 위험
